`product-definition` 스킬로 요구사항 문서를 작성한다.

## 1. 파일 준비

인자를 케밥케이스로 정규화한다 (`매장 검색 권한` → `store-search-permission`).
영문 슬러그를 사용자에게 확인받는다 — 파일명은 나중에 바꾸기 번거롭다.

```bash
ls docs/product/features/<슬러그>.md 2>/dev/null   # 이미 있으면 갱신 모드
cp docs/product/features/_TEMPLATE.md docs/product/features/<슬러그>.md
```

## 2. 맥락 파악

```bash
cat docs/product/product.md
cat docs/architecture/architecture.md
```

- `product.md` 의 **범위**에 이 기능이 들어가는가? 벗어나면 진행 전에 알린다
- `architecture.md` 로 이 기능이 어느 계층에 걸치는지 감을 잡는다

기존 코드에서 관련 부분을 찾아 둔다 (Grep/Glob). §6 구현 참고에 쓸 재료다.

화면이 있는 기능이면 `docs/product/design.md` 도 읽는다 (없으면 건너뛴다).

## 3. 작성

`product-definition` 스킬의 순서를 따른다.

```
배경 → §2 화면 설계 → §3 API → §4 흐름 → §5 완료 조건 → §6 구현 참고
     → §7 범위 외 → §8 결정 → 마지막에 §1-2 태스크 분리
```

**§1-2 를 맨 나중에 쓴다.** 문서 맨 앞에 있는 것은 추출기와 읽는 사람을 위한 배치다.
무엇을 만들지 모르면 쪼갤 수 없다.

각 큰 단계가 끝날 때 사용자에게 확인을 받는다. 문서 전체를 한 번에 쓰고 보여주지 않는다.

### 3-1. 화면이 있으면 §2 를 먼저 채운다

화면 없는 백엔드 전용 기능이면 §2 를 통째로 지우고 §3 으로 간다.

**2-2 참조를 건너뛰지 않는다.** 이 절이 이 섹션의 존재 이유다.

```
비슷한 서비스를 하나 열어 이 화면에 해당하는 부분을 보겠습니다.
도메인을 모르면 무엇이 빠졌는지 모릅니다.

  어떤 서비스를 참조할까요? (없으면 제가 찾아보겠습니다)
```

사용자가 URL·스크린샷을 주면 그것을 보고, 없으면 웹에서 찾아 제시한다.
**볼 것은 「무엇이 가장 크게 보이나」와 「우리 데이터에 없는 것」이다.**

찾은 것을 2-2 표에 적고 **대조 결과를 사용자에게 확인받는다** — 없는 것 중
이번에 넣을 것과 §7 범위 외로 둘 것을 가른다.

그다음 2-3 「담기는 것」을 채운다. **「데이터 출처」가 빈 행은 새 필드다.**
그 행이 하나라도 있으면 §3 API 명세와 마이그레이션이 필요하고, §1-2 의 백엔드
태스크 범위가 커진다 — 이것을 사용자에게 명시적으로 알린다.

```
포스터 이미지는 지금 데이터 모델에 없습니다.
넣으려면 performances 에 poster_url 컬럼과 마이그레이션이 필요하고,
백엔드 태스크가 그만큼 커집니다. 이번 범위에 넣을까요?
```

2-4 배치는 ASCII 로 그린다. 세로 목록인지 그리드인지 정하고 이유를 한 줄 적는다.
와이어프레임을 눈으로 보고 싶다는 요청이 있으면 아트보드를 Artifact 로 발행하고
링크만 문서에 건다 — 이미지를 저장소에 복사하지 않는다.

## 4. §1-2 검토

작성한 태스크 분리 표를 사용자와 함께 확인한다. 특히:

- 각 행이 4~16시간인가
- Backend / Frontend 가 다른 행인가. FE 행에 선행이 적혔는가
- "포함하지 않음"이 비어 있지 않은가
- "원인 분석만" / "QA만" 하는 행이 없는가
- **§2-3 의 신규 필드가 백엔드 행의 범위에 반영됐는가**

문제가 있으면 고친 뒤 넘어간다. 여기서 잘못 쪼개면 워크플로우 전체가 비용을 나눠 낸다.

## 5. 마무리

```bash
python3 scripts/rebuild_doc_index.py
python3 scripts/hooks/check_artifact_paths.py docs/product/features/<슬러그>.md
git add docs/product/ && git commit -m "docs(feature): <기능명> 요구사항"
```

```
docs/product/features/store-search-permission.md 작성

  화면 설계      참조 1건 대조 · 담기는 것 6개 (신규 필드 1) · 배치 그리드
  태스크 분리    2건 (Backend 8h → Frontend 6h)
  완료 조건      5건
  구현 참고      3개 경로 (신규 1)
  ADR 승격 후보  1건 — "권한 판정을 데코레이터로 통일"

다음: /wf-tasks-from-doc docs/product/features/store-search-permission.md
```

ADR 승격 후보가 있으면 `/wf-adr` 를 먼저 하자고 제안한다 — 태스크를 만들기 전에
결정이 확정되어 있으면 Phase 1이 그것을 참조할 수 있다.
