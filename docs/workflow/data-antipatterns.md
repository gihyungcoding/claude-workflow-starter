# 데이터 처리 안티패턴

Phase 산출물(JSON·Markdown)을 다룰 때 반복적으로 나타난 실패 패턴이다.

> **원본에서 바뀐 점**
> 원본에서 이 내용은 `1002`, `1003a`, `1003b` 3곳에 각 70줄씩 중복되어 있었다.
> 여기서는 이 파일이 정본이며, 스킬들은 이 문서를 링크로만 참조한다.

---

## 1. 텍스트 도구로 JSON 자르기 — 금지

```bash
# ❌ 금지
grep -A 2000 '"id": "TASK-019"' tasks.json | head -n 2500 > /tmp/task.json
sed -n '1200,1800p' PLAN_TASK-019.json
```

JSON 구조가 중간에 잘려 malformed JSON이 되고, 파싱 실패 → 같은 파일 재읽기 → 또 실패의
루프에 빠진다. 잘린 위치가 눈에 보이지 않아 디버깅도 어렵다.

```bash
# ✅ 권장 — 구조를 이해하는 도구를 쓴다
jq '.[] | select(.id == "TASK-019")' workflow_design/02_tasks/tasks.json
```

파일이 커서 전체 읽기가 부담스러우면 `jq` 로 **필요한 노드만** 뽑는다.
크기 때문에 `head`/`sed` 로 자르는 것은 해법이 아니다.

---

## 2. 파싱 실패 후 같은 방법 반복 — 금지

```
❌  파싱 실패 → 같은 파일 다시 읽기 → 파싱 실패 → 다시 읽기 → ...
```

같은 입력에 같은 방법을 쓰면 같은 결과가 나온다. **첫 실패에서 방법을 바꾼다.**

```
✅  1. 파싱 실패
    2. 에러 메시지에서 실패 위치 확인 (몇 번째 문자에서 깨졌는지)
    3. 원인 판정 — 파일이 실제로 malformed 인가, 내가 자른 것인가
    4. 방법 변경 후 1회 재시도
    5. 그래도 실패하면 사용자에게 파일 상태를 보고하고 멈춘다
```

같은 파일을 3번 이상 읽고 있다면 접근 방법이 잘못된 것이다.

## 3. 임시 파일에 부분 데이터 저장 — 금지

```bash
# ❌ 금지
jq '.scenarios' SCENARIO_TASK-019.json > /tmp/task019_scenarios.json
# ... 이후 단계에서 /tmp 파일을 다시 읽음
```

임시 파일은 (a) 원본과 어긋나도 알 수 없고, (b) 세션이 끊기면 사라지며,
(c) 어느 시점의 스냅샷인지 추적되지 않는다.

```
✅  파싱한 데이터를 컨텍스트에 두고 재사용한다.
    영속화가 필요하면 workflow_design/ 의 정본 경로에 쓴다 (→ artifact-paths.md).
```

예외: 독립검증자에게 넘길 프롬프트처럼 **한 번 쓰고 즉시 소비되는** 파일은 `/tmp` 에 둬도 된다.
다음 Phase가 읽는 데이터는 안 된다.

## 4. 산출물 파생 관계를 뒤집기 — 금지

Phase 2a/2b의 산출물에는 방향이 있다.

```
SCENARIO_<ID>.md      ← SoT. 사람이 편집한다.
      │ 파생
      ▼
SCENARIO_<ID>.json    ← 독립검증 통과 시점 스냅샷 (승인은 2b 끝 통합 HITL)
      │ supersede
      ▼
TEST_<ID>.json        ← 최종 파생물
```

- ❌ `SCENARIO_<ID>.json` 을 직접 편집하고 `.md` 를 그대로 두는 것
- ❌ `TEST_<ID>.json` 을 고쳐서 시나리오를 바꾸는 것

**MD를 고치고 JSON을 다시 생성한다.** 반대 방향은 없다.

---

## 5. 올바른 흐름

```
1. 로딩 (최초 1회)
   └─ Read 또는 jq 로 필요한 산출물을 읽는다

2. 파싱 및 검증
   └─ 실패하면 즉시 중단하고 보고 (반복 재시도 금지)

3. 컨텍스트에 유지
   └─ 이후 단계에서 파일을 다시 읽지 않는다
   └─ 필터링·변환은 메모리 데이터에서 한다

4. 영속화
   └─ artifact-paths.md 의 정본 경로에만 쓴다
   └─ 쓴 직후 커밋한다
```

## 6. 산출물 쓰기 — atomic

Phase 산출물을 덮어쓸 때는 임시 파일에 쓰고 원자적으로 옮긴다. 쓰기 도중 세션이 끊기면
반쯤 쓰인 JSON이 남아 다음 세션의 복구를 막는다.

```bash
TARGET="workflow_design/04_plan/PLAN_TASK-001.json"
# 기존 파일이 있으면 먼저 백업 (확장자 보존)
[ -f "$TARGET" ] && cp "$TARGET" ".backups/PLAN_TASK-001.$(date +%Y%m%d%H%M%S).json"
# 임시 파일에 쓴 뒤 이동
mv "$TMP" "$TARGET"
```

`.backups/` 는 `.gitignore` 대상이다 — 복구용 로컬 사본이지 산출물이 아니다.
